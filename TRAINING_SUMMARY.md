## 🛠 2. Шпаргалка по Git

### Базовые команды
| Команда | Описание |
| :--- | :--- |
| `git status` | Показать состояние файлов (изменения, индекс) |
| `git add <файл>` | Добавить конкретный файл в индекс |
| `git add .` | Добавить **все** изменённые и новые файлы |
| `git commit -m "Текст"` | Сохранить изменения локально с комментарием |
| `git push` | Отправить изменения текущей ветки на сервер |

### Работа с ошибками и историей
| Команда | Описание |
| :--- | :--- |
| `git commit --amend` | Исправить последний коммит (добавить забытые файлы или изменить текст) |
| `git reset HEAD <файл>` | Убрать файл из индекса (перед коммитом) |
| `git log --oneline -5` | Показать последние 5 коммитов кратко |

### Управление ветками
| Команда | Описание |
| :--- | :--- |
| `git branch` | Список локальных веток |
| `git branch -a` | Список всех веток (локальные + удалённые) |
| `git checkout -b <имя>` | Создать новую ветку и переключиться на неё |
| `git checkout <имя>` | Переключиться на существующую ветку |
| `git merge <ветка>` | Влить изменения из указанной ветки в текущую |
| `git push origin --delete <ветка>` | Удалить ветку на удалённом сервере |

### Синхронизация
| Команда | Описание |
| :--- | :--- |
| `git pull` | Скачать и применить изменения с сервера для текущей ветки |
| `git fetch` | Скачать изменения с сервера, но не применять их |

## ☁️ 3. GitHub Codespaces & Node.js

*   **Среда:** Полноценный редактор и терминал в браузере.
*   **Запуск сервера:** `node src/server.js` или `npm start`.
*   **Порты:** Codespaces автоматически открывает доступ к портам (например, 3000). Ищи кнопку **"Open in Browser"**.
*   **Зависимости:**
    *   Никогда не коммить папку `node_modules`.
    *   В репозитории должны быть только `package.json` и `package-lock.json`.
    *   Установка: `npm install`.

## ❓ 4. Блиц-опрос (Проверь себя)

Попробуй ответить на вопросы, не подглядывая в шпаргалку.

| № | Вопрос | Правильный ответ (скрыт, нажми для просмотра) |
| :--- | :--- | :--- |
| 1 | Я сделал коммит, но забыл добавить один файл. Как исправить историю, чтобы не было лишнего коммита? | `git add <файл>` затем `git commit --amend` |
| 2 | Агент накосячил в ветке `coder-test`. Как посмотреть список всех веток, чтобы найти её точное имя? | `git branch -a` |
| 3 | В чём разница между `git add .` и `git commit -a`? | `add .` добавляет файлы в индекс. `commit -a` сразу коммитит все *изменённые* файлы, пропуская этап `add` (но новые файлы всё равно требует `add`). |
| 4 | Почему команда `git push` иногда создаёт новую ветку на сервере? | Если ты находишься в локальной ветке, которой ещё нет на сервере, `push` создаст её там автоматически. |
| 5 | Где находится файл `index.html`, когда ты в ветке `main`, а агент менял его в ветке `coder-bad`? | На диске лежит версия из `main`. Изменения из `coder-bad` изолированы и не видны, пока ты не переключишься на ту ветку. |
| 6 | Как удалить ветку `old-feature` с сервера GitHub? | `git push origin --delete old-feature` |

## 📝 Чек-лист терминов

*   **Index (Staging Area)** — промежуточная зона, куда файлы попадают перед коммитом (`git add`).
*   **HEAD** — указатель на текущую ветку/коммит, где ты находишься.
*   **Origin** — стандартное имя для удалённого репозитория (твой GitHub).
*   **Pull Request (PR)** — запрос на слияние веток (основной способ попадания кода в `main`).
*   **Merge Conflict** — конфликт слияния, когда Git не может автоматически объединить изменения.
