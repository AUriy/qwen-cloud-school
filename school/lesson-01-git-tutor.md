# Git command

## Формат комманды
```text
 git        push       origin        main
  │          │          │             │
[Программа] [Действие] [Имя сервера] [Имя ветки]
```
* git — вызываем саму программу
* push — действие (буквально: "протолкнуть" или отправить код на сервер)
* origin — это имя (псевдоним) удаленного сервера. Когда вы клонируете репозиторий, Git автоматически дает серверу стандартное имя `origin` (источник), чтобы не писать каждый раз длинную ссылку вроде `https://github.com.main` (или master) — это название ветки на вашем компьютере, которую вы хотите отправить на этот сервер. Если бы этого разделения не было, `Git` не знал бы, куда отправлять код (ведь у одного проекта может быть несколько серверов, например, тестовый и рабочий) и какую именно ветку туда загружать.

## Начало работы и получение кода
* git init — создать новый локальный репозиторий в текущей папке
* git clone <ссылка> — скачать удаленный репозиторий на компьютер

## Сохранение изменений (каждый час)
* git status — проверить состояние файлов (что изменено, что готово к сохранению)
* git add . — добавить все измененные файлы в индекс для следующего сохранения
* git commit -m "сообщение" — сохранить изменения в истории с описанием того, что сделано

## Работа с ветками (изоляция фич)
* git branch — посмотреть список всех веток в проекте
* git checkout -b <имя_ветки> — создать новую ветку и сразу переключиться на нее
* git merge <имя_ветки> — влить изменения из указанной ветки в текущую

## Обмен кодом с сервером (в конце дня)
* git pull — скачать свежие изменения от коллег из сервера в свой компьютер
* git push origin <имя_ветки> — отправить свои сохраненные коммиты на сервер

## Прочие полезные команды Git (вкратце)

### Навигация и история
* git log — показать историю всех коммитов (кто, когда и что изменил). Выход из этого режима — клавиша Q
* git diff — показать изменения в файлах, которые еще не были сохранены (сравнить текущее состояние с прошлым коммитом). Отмена и исправление ошибок
* git restore <файл> — сбросить незакоммиченные изменения в конкретном файле (вернуть его к состоянию последнего коммита)
* git reset --hard HEAD~1 — опасная команда. Удаляет последний коммит и все изменения в файлах, возвращая проект на один шаг назад.

### Работа с удаленными серверами
* git remote -v — показать список подключенных удаленных репозиториев (вы увидите ту самую ссылку, которая прячется за словом origin)
* git fetch — проверить сервер на наличие обновлений от коллег, но не скачивать их в ваш код (безопасный осмотр)

### Как читать вывод
* git status — это ваш главный компас. Она делит файлы на три зоны, подсвечивая их разными цветами в терминале:Untracked files (Неотслеживаемые файлы — обычно красные): Это новые файлы, которые вы только что создали. Git еще ничего не знает о них. Чтобы он их заметил, нужно сделать git add.Changes not staged for commit (Измененные файлы — красные): Файлы, которые Git уже знал, но вы их отредактировали. Они еще не готовы к сохранению.Changes to be committed (Изменения, готовые к коммиту — зеленые): Файлы, для которых вы уже выполнили команду git add. При следующем git commit именно они сохранятся в историю.
